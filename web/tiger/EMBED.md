# Run-log chart on the judge guide

The chart is integrated into `web/judge/index.html`, immediately after
`#replay-evidence` and before the evaluation steps. `/judges/` is a legacy
redirect to `/judge/`; the live controls remain on `/live/`.

The guide loads `../tiger/chart.css` and `../tiger/chart.js` in its head and
mounts the chart inside `#run-log-evidence`:

```html
<div id="tiger-chart" data-snapshot="../tiger/snapshot.json">
  <p class="tgr-note">Enable JavaScript to view the run-log chart, or
    <a href="../tiger/snapshot.json">read the saved snapshot data</a>.</p>
</div>
```

The block uses the guide's charcoal/cyan tokens and local fonts, with matching
standalone fallbacks. It adds no library, backend connection, or media playback.
Links below the chart expose the saved JSON, SQL view definitions, and pipeline
README. Without JavaScript the recorded summary and direct JSON link remain
available. A missing or malformed snapshot displays an unavailable-data message;
it never substitutes sample evidence.

Every figure labels its source:

- `offline_fallback: true`: **Local snapshot · No Tiger Data query**.
- `offline_fallback: false`, generated by the actual database path:
  **Snapshot from Tiger Data queries**.
- Missing provenance: no chart or database badge.

Both successful cases are saved evidence, not current backend/database status.
Never change `offline_fallback` by hand. Regenerate with the appropriate
`snapshot.py` mode after validating or ingesting the logs as described in
[README.md](README.md).

For local inspection, run `python -m http.server --directory web` from the
repository root and open `http://localhost:8000/judge/#run-log-evidence`.
`http://localhost:8000/tiger/preview.html` shows the block alone.
`node web/demo-ui/dev/checks/site-checks.mjs` starts its own local server and
checks source labeling, the full set of saved runs, failure states, and layout
at phone and desktop widths without external requests.
