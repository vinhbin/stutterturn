# StutterTurn Technical Execution Implementation Plan

> **For agentic workers:** Apply the shared `subagent-driven-development` or `executing-plans` skill task by task. Checkboxes below describe proposed work, not completed work. Confirm current contracts before implementing a package; review its evidence before starting dependent work.

**Goal:** Make StutterTurn a reproducible, measurable turn-taking system whose model, actual audio behavior, and failure handling can be independently inspected.

**Architecture:** Extend the existing ONNX model, Python replay engine, versioned HTTP/WebSocket contract, and plain JavaScript adapter. Establish causal input and output measurements before adding transports. Preserve the approved visual system and the requested `/judge` guided-evaluation versus `/live` engineering-console separation.

**Tech stack:** Python, NumPy, ONNX Runtime, Silero VAD, Whisper feature extraction, the existing PyTorch/haan training branch, aiohttp, sounddevice for optional local playback, Gemini and ElevenLabs when explicitly enabled, plain HTML/CSS/JavaScript, Node and Playwright checks. Reuse the merged playback dependency; probe its behavior on the demo device before extending its contract.

**Spec:** This user-requested roadmap implements the direction “technical depth comparable to LOKA Pay.” Read [PLAN.md](../../../PLAN.md), [evening handoff](../../team-handoff-2026-10-10-evening.md), [model contract](../../../model/CONTRACT.md), and [agent contract](../../../agent/CONTRACT.md) together. This document neither changes product direction nor authorizes new public claims.

## What “same technical level” means here

LOKA Pay exposes a cross-platform payment protocol, hardware-key integration, on-chain validation and failure tests. Its public [redemption implementation](https://github.com/StephenSook/loka-pay/blob/main/programs/loka_vault/src/instructions/redeem.rs) enforces explicit invariants; its [lease-fencing tests](https://github.com/StephenSook/loka-pay/blob/main/server/src/settle/lease-fencing.test.ts) challenge stale workers; its [proof page](https://zerobars.us/proof) connects claims to inspectable evidence. Its [trust page](https://zerobars.us/trust) also states sandbox and unfinished capabilities. These were inspected on October 10, not independently reimplemented or audited.

StutterTurn's corresponding contribution is **a reproducible turn-taking improvement with a measured delay tradeoff, a working audio path, and credible failure handling**. The comparator is engineering discipline, not repository size, tool count, or a claim of parity with LOKA. Adding blockchain, another speech provider, or a larger website does not establish this contribution.

Source-time details matter: replay uses 512-sample frames at 16 kHz (**32 ms**), rounds the nominal 0.2 s VAD delay to **0.224 s**, and keeps six pre-roll frames (**0.192 s**). It resets turn context after a completed turn and resumed speech. The offline runner must reproduce actual sample slices and check points, not merely share a feature extractor. Replay adds five seconds of synthetic trailing silence; the offline benchmark censors at the real recording end. Never combine those outcomes without disclosing the difference.

Playback now shares the caller/agent sample timeline, but host `t0` is set after stream start and callback device time/status are ignored. This leaves clock alignment, consumed-versus-scheduled output and underrun evidence open. Earlier replay v2 remains model-input evidence, not a retrofit proof of the newly added `--play` path.

Publish a small integration example with no embedded credentials. Claim “drop-in” only for that tested version/configuration, not every voice platform.
- [ ] Specify live capture consent, push-to-start/stop, sample rate/channels, resampling, echo handling, backpressure, permission failure and disconnect cleanup. Raw microphone audio stays transient by default; diagnostic recording is an explicit opt-in with retention/deletion controls. Server logs omit transcripts/audio by default. Provider disclosure and any upload permission happen before streaming.
- [ ] Test denial/unplug/reconnect, background tab, packet jitter/loss, resampling drift, echo-triggered false barge-in and stale microphone chunks after reset. Demonstrate on actual hardware with a consenting speaker, without requesting imitated stuttering. Enforce the same queue/turn invariants and disclose changed latency.

**Acceptance/cut:** One documented consumer can integrate and reproduce behavior, and a consenting user can stop capture/output reliably. Telephony/8 kHz, multi-user hosting and production access controls need their own scoped contracts and data tests; do not bundle them into the first microphone increment.

## Rights, privacy and release checklist applying to both horizons

- SEP-28k annotations are documented as **CC BY-NC 4.0**; podcast audio copyright remains with its owners. `benchmark/data/LICENSE.md` covers supplied Apple code, not blanket audio redistribution. Keep attribution and do not commit/host source audio or include it in a public video until applicable permission is established.
- Preserve Smart Turn/haan license notices and upstream dataset provenance. The training branch proposes a noncommercial research release; treat that as the project's restriction, not a completed legal determination about every derived artifact. Verify artifact/data terms before distributing candidate weights or claiming commercial readiness.
- Public evidence uses source references/hashes and reviewed metadata. Remove local absolute paths, tokens, request headers and private conversation content. Unknown speaker identity remains unknown; do not deanonymize recordings to fill a manifest field.
- Test with synthetic PCM only for device/queue correctness; it is not synthetic stuttering or a replacement for real speech labels. Separate model-only, fake-provider, real-service, device-playback and acoustic-validation evidence in every manifest.

## Minimal execution order and handoff

Start **Package 1 (human labels + evaluation integrity)** and **Package 3 (playback)** independently. Existing model mechanical checks can continue without waiting for listening; Package 2's data use/selection waits for the relevant policy and validation gates. Package 4's deterministic race checks run in parallel with both, but its final evidence waits for accepted outputs. Packages 5–6 start only after the event and their stated prerequisites.

Each implementer hands over one reviewed increment with exact commit, modified file scope, commands/results, artifact hashes, unresolved limits and the next consumer. Vinh integrates one reviewed change at a time. Stop at the existing deadline and select the supported scope; no new tool or interface is a substitute for missing proof.
